# 让本地项目只留下真正要用的最终版

这次先检查了本地文件、最终交付校验值和 GitHub。公开的 jed-order-dashboard-promo 已经有完整定稿，问题在于本地同时存在原始历史工程与 output 里面的公开工程，还有两套依赖和渲染 / 混音中间结果，找文件麻烦，也占空间。

把已同步 GitHub 的最终工程提升到当前项目根目录，现在这里就是直接连接公开仓库的 Git 工作目录。保留两版最终 MP4、旁白、完整混音、配乐与音效、15 段语音、字幕、故事板、讲解稿、五比例封面、源码、提示词和验收记录。最终文件不再依赖那个套在 output 里的发布目录。

清掉了旧版交付、旧源码、依赖目录、构建缓存、验收抽帧、试音 / 重混副本、浏览器日志和产品参考克隆。需求原文和以前的工作总结留在本地，设为 Git 忽略；本次整理说明同步到公开仓库。需求原文含演示登录信息，不应因目录迁移误上传。

值得记住：先把全部公开跟踪文件暂存到项目外并逐个核对哈希，再清理。五张用户移动过的最终封面和两版中文名 MP4 都跟公开定稿核对一致。旧项目与产品参考的完整 Git 历史分别生成 bundle，并验证可恢复；旧封面候选也放在项目外备份中。备份具体位置记录在本地的「本地文件说明.txt」，没有把私人磁盘位置写进公开仓库。

整理后媒体清单仍是 57 个文件，五比例尺寸、13 场景 / 1800 帧、15 段语音和 72 个文档链接检查通过。项目文件体积由约 1.82 GiB 降为约 147.5 MiB，工作目录减少约 1.68 GiB。项目外保留历史备份，占用另计，不把转移备份算成磁盘净释放。

以后最终视频在 deliverables，封面在 deliverables/covers，说明在 docs。依赖删了但 package-lock 保留，需要编辑时 npm ci 就能恢复；运行输出继续进被忽略的 output，避免下一次又积累进 Git。旧 bundle 是本地恢复用，不能拿来推到公开仓库。

一句话亮点：**把近两 GB 的制作现场整理成约 148 MB 的开源最终工程，成片、音轨、封面和源码都能一眼找到。**
